# Исследование: точность, скорость и размер калькулятора; перенос вычислений в компилируемое ядро

Дата: 2026-11-13. Проверяемые версии: SquadCalc `9664362c9` (45.51.0), инструменты и диссертация `505fd93`,
Squad Ballistics `d433661`. Машина: 4 ядра с AVX2, 15 ГБ памяти, Node 26.11.1, rustc 1.99.1.

Документ отвечает на четыре вопроса владельца:

1. Правда ли, что функция траектории считает с ошибками?
2. Правда ли, что рельеф считается и учитывается некачественно?
3. Правда ли, что калькулятор медленный и большой, и поможет ли перенос на C, C++ или Rust?
4. Что нужно сделать, чтобы вычисления были точными, быстрыми и формально описанными на уровне диссертации?

Каждый вопрос проверен независимо: шесть отдельных проверок, каждая со своим кодом и своими замерами. Проверки не
опирались на существующие тесты проекта, потому что три реализации, согласные между собой, доказывают только общую
модель, а не её правильное решение.

## 1. Короткий ответ

| Утверждение | Вердикт | Главное число |
|---|---|---|
| Функция траектории считает с ошибками | **Не подтверждается для решателя.** Подтверждается для четырёх вспомогательных функций рядом с ним | 74 656 решений для 164 снарядов: промах относительно модели игры не больше 4,8 мм, для ракет с двигателем не больше 2,5 см |
| Высота рельефа считается некачественно | **Не подтверждается** | 732 000 точек на 6 картах: расхождение с независимой реализацией не больше 2,2 нм |
| Рельеф некачественно учитывается в выстреле | **Частично подтверждается** | Проверка «выстрел упирается в землю» берёт точки через 1 м и пропускает 0,60 % заблокированных линий, худший случай 6,5 м |
| Калькулятор медленный | **Не подтверждается для обычной работы.** Подтверждается для трёх тяжёлых функций | Одно решение 1–15 мкс, высота 0,06–0,2 мкс; карта огневых позиций 1,0–1,7 с, тепловая карта с точным регионом 4,3 с |
| Калькулятор большой | **Верно, но это данные, а не код** | Сайт 8,09 ГБ: картинки карт 82,1 %, высоты 13,3 %, код 0,027 % |
| Нужно переписать на C, C++ или Rust | **Ядро на Rust уже есть (5 952 строки, 91 тест, 0 `unsafe`), но страница использует его только для вокселей** | Rust быстрее JavaScript в 1,3–2,4 раза на решателе и в 22–40 раз на чтении высоты; данных, что C был бы быстрее Rust, нет |
| Формулы должны быть оформлены | **Верно. Это главный пробел** | В диссертации нет ни одной формулы в математической записи; у 19 вычислений формула не записана нигде |

Вывод для диссертации. Язык программирования почти ничего не решает там, где работает пользователь: всё, что он делает
мышью, уже занимает от микросекунд до одной миллисекунды. Решают три вещи: единое ядро вместо трёх копий расчёта,
точные алгоритмы пересечения вместо выборки по шагу, и формальная спецификация с доказанными оценками ошибки. Раздел 8
даёт порядок работ.

## 2. Баллистика

### 2.1 Что именно делает решатель

Модель взята из игры: сопротивления воздуха нет, тяжесть $g = k_g \cdot 9{,}80$ м/с², сервер двигает снаряд шагами по
20 мс. Решатель не является одной формулой. Он состоит из точных участков и численного поиска угла:

| Участок | Способ | Точность |
|---|---|---|
| Обычная парабола от оси качания ствола | Замкнутая формула (A.3) | Точная: медиана ошибки $10^{-16}$ рад против арифметики с 60 знаками |
| Двигатель вдоль оси ствола (С-5 у УБ-32) | Замкнутая формула (A.5) | Точная, если время работы двигателя кратно 20 мс |
| Полёт на предельной скорости | Замкнутая формула (A.6) | Точная для непрерывной модели |
| Двигатель вдоль траектории, пуск выше предельной скорости | Полёт шагами игры по 20 мс, таблица по углу через 1°, интерполяция Лагранжа по 4 точкам | Воспроизводит шаговую схему игры до 2,5 см |
| Угол для цели, когда дульный срез смещён, есть двигатель или предел скорости | Поиск вершины золотым сечением, затем корень методом Иллинойс (A.7) | Допуски $10^{-9}$ м и $10^{-10}$ рад |

Замкнутой формулой угла пользуются только 42 из 163 снарядов с тяжестью. Обычный миномёт (дульный срез смещён на
1,569 м), все 38 ракет с двигателем и 33 из 38 быстрых снарядов с пределом скорости решаются численно.

### 2.2 Независимая проверка

Написан отдельный интегратор на C по описанию модели, не по коду калькулятора. Каждый угол, который выдаёт
калькулятор, пролетён этим интегратором двумя способами: шагами игры по 20 мс и непрерывным уравнением (метод
Рунге-Кутты 4 порядка, шаг 1 мс). Сетка: 164 снаряда, дистанции от 0,5 м до 8000 м и доли дальности каждого оружия,
10 высот цели от −300 до +200 м, обе дуги.

Промах в метрах: медиана / 99-й процентиль / максимум.

| Класс (число снарядов) | Случаев | Калькулятор против непрерывной модели | Калькулятор против шагов игры | Шаги игры против непрерывной модели |
|---|---:|---|---|---|
| Миномёты, обычная парабола (22) | 4 975 | 7e-11 / 1,1e-7 / 1,9e-7 | 1,5e-4 / 8,7e-4 / 8,8e-4 | то же |
| Гаубицы, «Град», HIMARS (7) | 1 721 | 5e-11 / 2e-9 / 5e-8 | 3,2e-4 / 9,6e-4 / 9,8e-4 | то же |
| Гранаты прямой наводки (33) | 5 714 | 1e-11 / 4e-8 / 9e-8 | 2,5e-4 / 4,9e-4 / 4,9e-4 | то же |
| УБ-32, двигатель по оси (2) | 266 | 4e-11 / 4e-8 / 5e-8 | 7e-4 / 1,3e-3 / 1,3e-3 | то же |
| Снаряды с пределом скорости (23) | 3 667 | 5e-11 / 0,48 / 0,78 | 5,6e-4 / 2,1e-3 / 4,8e-3 | 7e-4 / 0,48 / 0,78 |
| Быстрые пушки с пределом скорости (38) | 4 990 | 2e-3 / 1,9 / 2,0 | 6,6e-4 / 1,9e-3 / 3,0e-3 | 2e-3 / 1,9 / 2,0 |
| Двигатель вдоль траектории (38) | 4 040 | 0,18 / 1,6 / 3,0 | 2e-4 / 9e-3 / 2,5e-2 | 0,18 / 1,6 / 3,0 |

Что это значит:

- **Решатель точно воспроизводит модель игры.** Миллиметры для обычных снарядов и не больше 2,5 см для ракет.
- **Миллиметровый остаток объясним.** Шаговая схема игры для постоянного ускорения точна в узлах шага (лемма A.2), а
  между узлами игра ведёт снаряд по хорде. Хорда ниже параболы не больше чем на $g\,\Delta t^2/8$, то есть 0,49 мм при
  $k_g = 1$ и 0,98 мм при $k_g = 2$. Замер 0,88–0,98 мм совпадает с этой оценкой.
- **Сама игра расходится с идеальной физикой до 3,0 м.** Это свойство её шаговой схемы для ракет и снарядов с пределом
  скорости (худший случай реактивная граната PF-98), а не ошибка калькулятора. Калькулятор обязан повторять игру.
- **Чувствительность к шагу.** Если бы сервер шагал не по 20 мс, ракеты ушли бы на 1,9 м (144 Гц) – 4,2 м (20 Гц).
  Обычные параболы остались бы в пределах 6 мм. Кадр сервера измерен 2026-11-14 по его журналам: 20,052 мс, а не
  20,000; что это меняет, разобрано в разделе 2.4.

Дополнительно: 169 200 случаев сравнения JavaScript и Rust, 65 600 случаев полного расчёта от дистанции 0 до 1,3
дальности при высотах ±10 км. Исключений, бесконечностей и неожиданных NaN нет. Высота как функция угла имеет один
максимум на всех 1 141 проверенных парах «снаряд – дистанция», то есть корней не больше двух.

### 2.4 Кадр сервера и последний кадр двигателя (проверка 2026-11-14)

Обе величины, которые раньше были выводом из настроек, получены из самого сервера, без выстрелов в игре.

**Кадр измерен по журналам.** Сервер раз в 10 секунд пишет свою частоту (`Server Tick Rate`). В журналах боевого
сервера 48 055 таких записей за 133,5 часа: медиана 49,87 Гц, первый процентиль 49,57 Гц, 99,51 % записей не ниже
49,5 Гц, 83 записи (0,17 %) ниже 45 Гц. Тренировочный сервер даёт ту же медиану на 651 записи. Кадр по медиане
равен 20,052 мс. Независимая сверка: мировое время, которое сервер печатает в двух записях о выстреле, выросло на
23,619521 с за 1 178 кадров, то есть 20,0505 мс на кадр. Настройки частоты в параметрах запуска и в конфигурации
сервера нет, предел 50 Гц задан игрой; сервер не добирает до него 0,05 мс на кадр.

**Правило двигателя прочитано в двоичном файле сервера** (сборка 26005357, адреса в архиве проверок, `tick/binary/`):

- Тяга действует, только пока $\mathrm{float}(t_0 + T) > t$ со строгим неравенством, где $t_0$ время создания
  снаряда, $t$ мировое время (функция по адресу `0xa747770`).
- Снаряд создаётся внутри сетевого вызова `ServerFireProjectileWithId` (`0xa74f290`), без отложенного запуска и без
  поправки на задержку клиента.
- В кадре сервера сетевые вызовы выполняются до продвижения мирового времени, а такты объектов после него
  (`UWorld::Tick`, `0x804d3a0`). Поэтому на $k$-м такте снаряда $t - t_0 = k\,\Delta t$.

Отсюда число тактов с тягой:

$$N = \left\lceil \frac{T}{\Delta t} \right\rceil - 1 .$$

Калькулятор берёт $\lceil T/\Delta t\rceil$ тактов по 20,000 мс, то есть на один такт больше и с другим кадром. Одно
звено выведено из стандартного поведения движка, а не прочитано в файле: первый такт снаряда происходит в кадре его
создания. Если бы он происходил кадром позже, верным было бы число $\lceil T/\Delta t\rceil$.

Сдвиг точки попадания против модели калькулятора на 14 932 решениях (каждое пятое из раздела 2.2) в пределах
ограничений каждого оружия, метры поперёк траектории:

| Случай | Двигатель по оси (УБ-32), 52 случая | Двигатель по траектории, 811 случаев |
|---|---|---|
| Кадр 20,052 мс, число тактов прежнее | медиана 0,39, максимум 3,50 | медиана 0,001, максимум 0,22 |
| Кадр 20,052 мс, на такт меньше (правило сервера) | медиана 1,10, максимум 9,90 | медиана 0,002, максимум 1,18 |

Худшие случаи по правилу сервера: УБ-32 на пикапе 9,90 м на 2 183 м, УБ-32 6,74 м, РПГ-7 с ТБГ-7В 1,18 м на 450 м,
РПГ-7 с ПГ-7ВР 1,06 м на 340 м, PF-98 0,85 м. У 12 из 40 записей с двигателем сдвиг где-то в рабочих пределах больше
0,5 м; у СПГ-9 и «Грома» не больше 0,06 м. Снаряды без двигателя сдвигаются меньше чем на 1 мм.

Время создания хранится числом одинарной точности. При мировом времени больше 16 384 с его округление доходит до
2 мс при запасе $m \cdot 0{,}052$ мс для двигателя на $m$ кадров, поэтому у коротких двигателей в долгой сессии
число тактов изредка может отличаться на единицу. Частота этого не измерена.

Попаданий мин и ракет в журнале сервера нет: он записывает точки взрыва только ручных гранат. Задача на исправление
модели в трёх реализациях: deadline-squad/deadline-squadcalc#49.

## 3. Рельеф

### 3.1 Высота в точке

Высота читается по правилу треугольников игры (формулы A.8–A.11). Независимая реализация, написанная по описанию
формата, совпала с калькулятором на 732 000 случайных точек шести карт: расхождение не больше $2{,}2\cdot10^{-9}$ м.

| Величина | Значение |
|---|---|
| Шаг квантования высоты $\Delta$ | от 1,00 мм (Al Basrah, Mutaha) до 16,24 мм (Skorpo); ошибка не больше $\Delta/2$ |
| Сдвиг относительно отдельного файла рельефа | нет; медиана разницы 1,2 см при шаге того файла 5 см |
| Билинейная интерполяция вместо правила треугольников, 99-й процентиль | 1,1–15 см |
| Билинейная интерполяция, максимум | 1,1–59 м (обрыв на Skorpo 59 м, Fallujah 10,8 м) |
| Ближайший узел вместо правила треугольников, 99-й процентиль | 0,15–0,97 м |
| Мелкая сетка у стен | меняет высоту больше чем на 10 см в 72–80 % точек внутри своих ячеек |

Строки про билинейную интерполяцию показывают цену «очевидного» метода: до 59 м ошибки на обрыве.

Найдено три мелких дефекта чтения высоты:

- На границе ячеек с мелкой сеткой и без неё поверхность имеет разрыв 0,20–0,48 м.
- За пределами сетки и для нечисловой координаты возвращается 0, без ошибки. С карты до этого не добраться.
- Если мелкая сетка не загрузилась, калькулятор молча считает без неё, сообщение только в консоли.

### 3.2 Выстрел против рельефа

Проверка «снаряд упирается в землю» берёт точки пути через $\min(1\ \text{м}, s)$, где $s$ шаг сетки, и сравнивает
высоту пути с высотой земли. Первые и последние 3 м не проверяются. Между точками ничего не вычисляется.

Проверено на 54 000 реальных линий (6 карт, 3 оружия, по 3000 линий) против точного теста, который обходит каждый
треугольник под линией и решает пересечение параболы с плоскостью треугольника:

| Величина | Значение |
|---|---|
| Линий, заблокированных по точному тесту | 39 649 |
| Из них найдено калькулятором | 39 413 |
| Пропущено | 236 (0,60 %); Mk19 1,32 %, танк 0,35 %; Fallujah 1,08 % |
| Ложных блокировок | 0 |
| Глубина пропущенного препятствия | медиана 5 см, 90-й процентиль 0,24 м, худший случай 6,5 м |

Зависимость от шага выборки:

| Шаг, м | 0,25 | 0,5 | 1 | 3 | 5 |
|---|---:|---:|---:|---:|---:|
| Пропущено линий из 54 000 | 64 | 130 | 247 | 704 | 1 076 |
| Худшая глубина, м | 1,3 | 1,6 | 6,5 | 31 | 29 |

Карта огневых позиций использует шаг до 3 м и пропускает последние 5–12,5 м перед целью. Уменьшение шага ошибку не
убирает, а только сокращает. Убирает её точный тест (раздел 7.1).

### 3.3 Крыша или пол

Карта высот хранит одну высоту на точку: объекты слиты с землёй по максимуму. Цель на здании получает высоту крыши.
На Fallujah для крыши на 6,5 м выше пола при дистанции 600 м:

| Оружие и дуга | Сдвиг угла | Перелёт за точку на полу |
|---|---|---|
| Миномёт, настильная дуга | +11,8 тыс. | 25 м |
| ЗиС-3, настильная дуга | +11 тыс. | 493 м |
| Навесные дуги | около 0 | меньше 2 м |

Для настильного огня в городе это заметная ошибка, если стрелок целится в пол, а не в крышу. Объёмный слой даёт выбор
высоты цели, но он выключен по умолчанию.

## 4. Скорость

Замеры в процессорном времени одного потока, медиана нескольких запусков. JavaScript измерен в Node: это тот же движок
V8, что в Chrome, но времена в браузере не проверены. Разброс между запусками на общей машине до 25 %.

- Rust быстрее V8 в 1,3–2,4 раза на численном решателе и в 4,6–6,2 раза на обычной параболе.
- **Для РПГ-7 нынешний Rust в 10 раз медленнее JavaScript.** Он заново строит таблицу двигателя на каждый вызов

- **Цена границы.** Один вызов из JavaScript в модуль стоит 0,4–2,3 мкс. Передача через текст JSON стоит 16–50 мкс,
  в 5–10 раз больше самого расчёта. Перенос кода в ядро без пакетной передачи может замедлить, а не ускорить.

Чтение высоты: Rust 4–8 нс против 57–208 нс в JavaScript, в 22–40 раз быстрее. Но нынешний Rust не умеет поворот
сетки и мелкую сетку у стен, то есть заменить им страницу пока нельзя (на Skorpo ошибка 105 м в 3 км от начала сетки).

### 4.5 Был бы C быстрее этого Rust

Данных в пользу этого нет.

- Сборка уже идёт с полной оптимизацией: уровень 3, оптимизация при компоновке, одна единица кодогенерации.
- В горячих циклах обхода вокселей и дерева нет ни одной проверки границ массива (проверено по машинному коду). Они
  есть только в двоичном поиске по столбцу, три ветки.
- Rust и компилятор clang для C используют один генератор кода LLVM.
- На больших картах время определяют промахи кэша, а не команды: отрезок 50 м стоит 3,3–5,3 мкс на Jensen и
  22–31 мкс на Yehorivka при одном и том же коде.
- Литература: в браузере код медленнее машинного на 45–55 % (Jangda и др., 2019). Rust медленнее C в среднем в 1,77
  раза в микротестах, и почти вся разница это проверки, которые в горячих циклах здесь отсутствуют (Zhang и др.,
  2022). Цель «браузер» стоит дороже, чем выбор между C и Rust.

Перенос 5 952 строк и 91 теста на C потребовал бы заново построить весь проверочный контур и добавил бы риск ошибок
памяти в разборщиках файлов. Измеримого выигрыша он не обещает. Управляемость, которую даёт C, достигается иначе:
экспортом функций ядра с интерфейсом C (раздел 8, шаг 7).

## 7. Что важнее языка: алгоритмы

### 7.1 Точное пересечение параболы с рельефом

Ячейка карты высот это два плоских треугольника с фиксированной диагональю. Над каждым треугольником разность «высота
пути минус высота земли» есть квадратный трёхчлен от расстояния вдоль линии (формула A.13). Значит точный ответ даёт
обход ячеек под линией (алгоритм Аманатидеса–Ву в двух измерениях) с решением одного квадратного уравнения на
треугольник. Выборка по шагу не нужна, пропусков нет по построению.

Ускорение обхода: пирамида максимумов высот (Tevs, Ihrke, Seidel, 2008). Если максимум земли в блоке ниже минимума
пути над блоком, блок пропускается целиком. Отрезок пути между узлами шага игры является хордой, поэтому хватает
пересечения отрезка с треугольником, а отклонение хорды ограничено леммой A.2.

Эталон такого теста уже написан при проверке (раздел 3.2) и сверен с плотной выборкой до $2{,}8\cdot10^{-13}$ м.

### 7.2 Рассеивание по траектории

Заменить формулу ровной земли двумя решениями на углах $\theta \pm \sigma/2$ с пересечением с реальным рельефом
(формула A.14). Убирает ошибку Б2 (до 9,3 раза).

### 7.3 Один решатель вместо приближений

Сетка целей, анимация и кольцо дальности должны вызывать тот же решатель. Убирает Б1, Б3, Б4. Стоит микросекунды.

### 7.4 Устойчивое вычисление корней

Настильный корень вычислять без вычитания близких чисел (формула A.4). Сейчас потеря точности до
$7{,}4\cdot10^{-12}$ рад, при слабой тяжести до $8{,}6\cdot10^{-10}$ рад. В игре это не заметно, но в диссертации
нужна формула, устойчивая по построению, со ссылкой на Forsythe (1966) и Boldo (2009).

### 7.5 Одна библиотека математических функций

Опыт на миллионе аргументов: `atan` в V8 и в Rust на процессоре даёт разный последний бит в 6,14 % случаев, `sin` в
3,25 %, `atan2` в 12,57 %. В браузерном модуле Rust совпадает с V8 по `atan`, `tan`, `atan2`, но расходится по `sin`
(0,88 %) и `cos` (0,93 %). Стандарт языка JavaScript точность этих функций не задаёт. Вывод: побитового совпадения
между JavaScript, браузерным модулем и машинным кодом обещать нельзя. Единое ядро со своей математикой даёт один и
тот же результат на любой машине, а сравнение с другими реализациями ведётся с заявленным допуском.

### 7.6 Видеокарта

Шейдеры считают в `f32`, а стандарт шейдерного языка допускает для `atan` ошибку в 4096 единиц последнего разряда.
Видеокарта годится для массовых проверок видимости с допуском, решение наводки остаётся в `f64` на процессоре. В
Firefox под Linux вычислений на видеокарте в браузере нет.

## Приложение A. Формулы

Обозначения: $\theta$ угол возвышения ствола; $v$ начальная скорость, м/с; $g$ тяжесть, м/с²; $D$ горизонтальная
дистанция от оси качания до цели, м; $H$ высота цели над землёй под оружием, м; $\Delta t = 0{,}02$ с шаг модели
(измеренный кадр сервера 20,052 мс, раздел 2.4).

### A.1 Модель и шаг игры

Непрерывная модель: $\ddot{\mathbf r} = \mathbf a(\mathbf R) + \mathbf g$, где $\mathbf g = (0, -g)$,
$g = k_g \cdot 9{,}80$, а $\mathbf a(\mathbf R)$ ускорение двигателя величины $a$ вдоль направления снаряда
$\mathbf R$ в течение времени $T$.

Шаг игры, для скорости $\mathbf v_n$ и положения $\mathbf p_n$:

$$\mathbf U(\mathbf R) = \operatorname{clamp}_{V}\!\big(\mathbf v_n + (\mathbf a(\mathbf R) + \mathbf g)\,\Delta t\big),$$

$$\mathbf p_{n+1} = \mathbf p_n + \tfrac12\big(\mathbf v_n + \mathbf U(\mathbf R_n)\big)\,\Delta t,\qquad
\mathbf R_{n+1} = \frac{\mathbf v_n}{|\mathbf v_n|},\qquad \mathbf v_{n+1} = \mathbf U(\mathbf R_{n+1}),$$

где $\operatorname{clamp}_V$ ограничивает модуль скорости значением $V$ (`MaxSpeed`). Направление $\mathbf R$
обновляется, только если снаряд поворачивается за скоростью; у С-5 оно остаётся осью ствола. Двигатель при этом
толкает вдоль пути с опозданием на один шаг в перемещении.

### A.2 Лемма о шаге

При постоянном ускорении и без ограничения скорости узлы $\mathbf p_n$ лежат на непрерывной параболе точно:
$\mathbf p_n = \mathbf p_0 + \mathbf v_0 t_n + \tfrac12 \mathbf g\, t_n^2$, $t_n = n\,\Delta t$. Между узлами игра
ведёт снаряд по хорде. Наибольшее отклонение хорды от параболы по вертикали

$$\delta_{\max} = \frac{g\,\Delta t^2}{8},$$

то есть 0,49 мм при $g = 9{,}80$ и 0,98 мм при $g = 19{,}6$.

Для отрезка пути с горизонтальной длиной $L$ при горизонтальной скорости $v_x$ то же отклонение равно
$g L^2 / (8 v_x^2)$.

### A.3 Обычная парабола: углы, область достижимости, дальность

Путь от оси качания: $y(x) = x\tan\theta - \dfrac{g x^2}{2 v^2 \cos^2\theta}$.

Условие попадания в точку $(D, H)$ есть квадратное уравнение относительно $\tau = \tan\theta$:

$$\frac{g D^2}{2 v^2}\,\tau^2 - D\,\tau + \Big(H + \frac{g D^2}{2 v^2}\Big) = 0,
\qquad \Delta = v^4 - g\,(g D^2 + 2 H v^2),$$

$$\theta_{\mp} = \arctan\frac{v^2 \mp \sqrt{\Delta}}{g D}.$$

Знак минус даёт настильную дугу, плюс навесную. Решение существует при $\Delta \ge 0$, то есть под параболой
безопасности

$$H \le \frac{v^2}{2g} - \frac{g D^2}{2 v^2}.$$

Наибольшая дальность при высоте цели $H$: $D_{\max}(H) = \dfrac{v}{g}\sqrt{v^2 - 2 g H}$; на ровной земле $v^2/g$.
Время полёта: $t = \dfrac{D}{v\cos\theta}$.

### A.4 Устойчивая форма настильного корня

По теореме Виета $\tau_- \tau_+ = 1 + \dfrac{2 H v^2}{g D^2}$, откуда без вычитания близких чисел

$$\tau_- = \frac{g D^2 + 2 H v^2}{D\,(v^2 + \sqrt{\Delta})}.$$

### A.5 Дульный срез и двигатель по оси

Ось качания на высоте $h$, дульный срез на расстоянии $f$ вдоль ствола и $u$ над его осью:

$$x_0 = f\cos\theta - u\sin\theta,\qquad y_0 = h + f\sin\theta + u\cos\theta.$$

Точка старта зависит от $\theta$, поэтому при $f \ne 0$ или $u \ne 0$ уравнение A.3 перестаёт быть квадратным
относительно $\tan\theta$ и решается численно (A.7).

Двигатель с ускорением $a$ вдоль неподвижной оси ствола $\hat{\mathbf e}$: положение
$\mathbf p(t) = \mathbf p_0 + \hat{\mathbf e}\,L(t) + \tfrac12\,\mathbf g\,t^2$, где путь вдоль оси
$L(t) = v_0 t + \tfrac12 a t^2$. Обратная функция в устойчивой форме:

$$t(L) = \frac{2L}{v_0 + \sqrt{v_0^2 + 2 a L}}.$$

Полное ускорение $a\,\hat{\mathbf e} + \mathbf g$ постоянно, поэтому участок с двигателем и участок после него есть
две параболы, сшитые в момент $T$.

### A.6 Полёт на предельной скорости

Модуль скорости постоянен и равен $V$, угол пути $\gamma$ меняется по закону $\dot\gamma = -g\cos\gamma / V$. С
радиусом $R = V^2/g$ и значениями $x_c, y_c, t_c, \gamma_c$ в момент выхода на предел:

$$x = x_c + R\,(\gamma_c - \gamma),\qquad y = y_c + R\,\ln\frac{\cos\gamma}{\cos\gamma_c},\qquad
t = t_c + \frac{V}{g}\big(\operatorname{artanh}\sin\gamma_c - \operatorname{artanh}\sin\gamma\big).$$

Момент выхода на предел при свободном падении: $t = \dfrac{v_y + \sqrt{V^2 - v_x^2}}{g}$.

### A.7 Численный поиск угла

Пусть $y(\theta, D)$ высота снаряда на дистанции $D$ при угле $\theta$, а $F(\theta) = y(\theta, D) - H$.

1. Вершина $\theta^\ast = \arg\max_\theta y(\theta, D)$ на $[-\pi/2 + 10^{-6},\ \pi/2 - 10^{-6}]$ методом золотого
   сечения до ширины интервала $10^{-10}$ рад (52 шага).
2. Если $F(\theta^\ast) < 0$, цель недостижима.
3. Каждый корень заключается в интервал от $\theta^\ast$ шагом 0,02 рад с удвоением.
4. Интервал $[a, b]$ сужается методом Иллинойс: $c = \dfrac{a F(b) - b F(a)}{F(b) - F(a)}$; если один и тот же конец
   заменён дважды подряд, значение $F$ на другом конце делится на 2. Остановка при $|F(c)| \le 10^{-9}$ м или ширине
   интервала меньше $10^{-10}$ рад, не больше 200 шагов.

Метод опирается на то, что $y(\theta, D)$ имеет один максимум. Для обычной параболы это следует из A.3; для остальных
классов проверено численно (раздел 2.2).

### A.8 Точка карты в мировые метры

Для точки карты с координатами $(\varphi, \lambda)$ в единицах $P = 256$ и границ миникарты:

$$x = x_{\min} + \lambda\,\frac{x_{\max} - x_{\min}}{P},\qquad y = y_{\min} - \varphi\,\frac{y_{\max} - y_{\min}}{P}.$$

Масштабы по осям различны на неквадратных картах (Skorpo 6849 × 6869 м).

### A.9 Мировые метры в узел сетки высот

Сетка задана началом $\mathbf o = (o_x, o_y)$, шагом $s$ и поворотом $\psi$:

$$c = \frac{(x - o_x)\cos\psi + (y - o_y)\sin\psi}{s},\qquad r = \frac{-(x - o_x)\sin\psi + (y - o_y)\cos\psi}{s}.$$

Композиция A.8 и A.9 аффинна, шесть её коэффициентов вычисляются один раз на карту.

### A.10 Уровень в метры

$$h = \Delta \cdot L,\qquad \Delta = \max\!\Big(\frac{z_{\max} - z_{\min}}{65535},\ 1\ \text{мм}\Big),\qquad
L = \operatorname{round}\frac{z - z_{\min}}{\Delta}.$$

Ошибка квантования $|e| \le \Delta/2$, среднеквадратичная $\Delta/\sqrt{12}$.

### A.11 Интерполяция в ячейке: правило треугольников

Для ячейки с углами $L_{00}, L_{01}, L_{10}, L_{11}$ и дробными координатами $u, v \in [0, 1]$, диагональ от $(0,0)$
к $(1,1)$:

$$\tilde L = \begin{cases}
(1 - u)\,L_{00} + (u - v)\,L_{01} + v\,L_{11}, & u \ge v,\\[2pt]
(1 - v)\,L_{00} + (v - u)\,L_{10} + u\,L_{11}, & u < v.
\end{cases}$$

Отличие от билинейной интерполяции равно $\tau\,v(1 - u)$ при $u \ge v$ и $\tau\,u(1 - v)$ иначе, где
$\tau = L_{00} - L_{01} - L_{10} + L_{11}$; наибольшее значение $|\tau|/4$ в центре ячейки.

У стен ячейка делится пополам по каждой оси, и то же правило применяется к четырём малым ячейкам.

### A.12 Проверка выстрела выборкой (как сейчас)

$$x_k = 3 + k\,\min(1, s),\quad x_k \le D - 3;\qquad \text{препятствие в } x_k \iff z_w + \zeta(x_k) < G(x_k),$$

где $z_w$ высота земли под оружием, $\zeta$ высота пути над ней, $G$ высота земли по A.11.

Для стенки высотой $W$ в один узел сетки при шаге выборки $q$ и шаге сетки $s$ скрытая глубина порядка $W q / (2 s)$:
для стенки 3 м при $s = 1$ м это 0,37 / 0,75 / 1,50 / 2,99 м при $q$ = 0,25 / 0,5 / 1 / 2 м.

### A.13 Точное пересечение (предлагается)

Над одним треугольником земля вдоль линии огня есть прямая $G(x) = \alpha + \beta x$, а путь на участке свободного
полёта есть парабола $\zeta(x) = \zeta_0 + \tau x - \kappa x^2$, $\kappa = g / (2 v_x^2)$. Разность

$$\zeta(x) + z_w - G(x) = (\zeta_0 + z_w - \alpha) + (\tau - \beta)\,x - \kappa\,x^2$$

есть квадратный трёхчлен. Его корни на отрезке, который линия проходит внутри треугольника, дают точку входа в землю
либо доказывают её отсутствие. Корни вычисляются в устойчивой форме, как в A.4.

На участках с двигателем и на предельной скорости путь игры есть ломаная из хорд шага A.1. Каждая хорда прямая,
поэтому тест сводится к пересечению отрезка с треугольником и точен относительно пути игры для всех классов оружия.

### A.14 Рассеивание

Сейчас. Поперёк: $w = \sin(\sigma)\, v\, t$, где $\sigma$ угловое рассеивание и $t$ время полёта. По дальности, для
ровной земли:

$$\ell = \frac{v^2}{g}\,\Big|\sin 2\big(\theta + \tfrac{\sigma}{2}\big) - \sin 2\big(\theta - \tfrac{\sigma}{2}\big)\Big|.$$

Предлагается: $\ell = \big|X(\theta + \tfrac{\sigma}{2}) - X(\theta - \tfrac{\sigma}{2})\big|$, где $X(\theta)$
дистанция точки падения на реальный рельеф по A.13.

### A.15 Зона поражения

Урон на расстоянии $r$ от взрыва при внутреннем радиусе $r_i$, внешнем $r_o$, показателе спада $\phi$:

$$d(r) = d_{\max}\Big(1 - \frac{r - r_i}{r_o - r_i}\Big)^{\phi},\quad r_i \le r \le r_o.$$

Радиус, на котором урон равен $\delta$: $r(\delta) = r_o - (\delta / d_{\max})^{1/\phi}\,(r_o - r_i)$. Радиус на земле
для цели ростом $1{,}8$ м при взрыве на высоте $z$: $\sqrt{r^2 - (z - 1{,}8)^2}$.

Число снарядов для уверенности $c$ при вероятности попадания одного $p$:

### A.16 Азимут и сетка

Азимут по смещениям на восток $e$ и север $n$: $\beta = \operatorname{atan2}(e, n)$ в градусах, приведённый к
$[0, 360)$. Дистанция $D = \sqrt{e^2 + n^2}$. Квадрат сетки имеет сторону 300 м и делится на $3 \times 3$ три раза.
